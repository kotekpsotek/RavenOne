## What is RavenOne
> Originally One-by-one but as default is parallel

**Short message:** `One list of points. One document of results.`

#### Then points for promoting:
- `Get what you need faster` / `Get your results faster` /  `Get your answers faster` / `Get your tasks be done faster`
Description: All points are processed in parallel what gives you faster result

- `Documents of Answers` / `- your know-how set` - for some group/s it can work decently
Description: Each set of answers is stored as document. You can edit this document then to align the answers you got in the rest of content - you can then share these documents
    - Documents are shareable

- `Parallelism`
Description: Parallel processed tasks share its state to others for better ourcomes

- `Tasks`
Description: Order tasks by pointing them and your agent will do it for you following your instructions and its knowledge along skilss

- `Processing Blackbox`
Description: Each Agent/LLM movement is decently documented what puts a glance to its internal monologue

- `Skills`
Description: Your agent is set of skills suited for tasks you use to solve either acquired in processing your tasks, took from **community shop**, hand-wroten; Skills are stored as folders with files where folder is category of skill e.g: Programming and files are skills. Folder can contain n next layers of subfolder-with-files

- `Knowledge`
Description: Knowledge is set of experiences e.g: how to solve some task - your agent has this knwoeldge developing while interacting with your questions

- `Dynamic agents picking from community`
Description: In `Dynamic Mode` agents are picked up from community with purpose in head to get the best agent for result
    - ***Community Agents*** are rated according to tasks specificity - so task managing agent knows what agent will be the best for this given task - base on `MEMRL` (Task - Solution - Experience)

- `Community of sharables/extensions`
Description: Leverage of plugins, skills, tools and addons for your editor. You can for instance, Use it to corelate visually knowledge of correlated questions and documents

## Possible modes
1) Sequential - PRocesses information sequentially; correlates knowledge in document together in response. E.g: Developing product strategy from all questions. Means model processes each response separatelly one-atime but is aware of below questions and above questions with answers - by processing aboce can leave information for these tasks processed below
2) S-Parallel (Separate Parallel) - each question is processed separatelly in parallel without sharing the state of processing
3) Parallel - processes all questions together in parallel and shares the state of processing between **cases**
    - shares e.g with: 
        - messaging - "Hi I'm TeleBot working for him to find the new Phone but i see that you're seeking the Tablet perhaps he (user) has fixed budget 2000$. Could we work together to find the devices are working together to give him best experience?"" - ACP protocol likelly or custom
        - skills - if required models can write skills together, overwrite and share them among themself
        - **?** task delegating - if agent see these 2 tasks are very similar they can then work together to solve this one task or agent can delegate part of job to other agent will work for that task or sth like this
4) auto - chooses the best mode for given task

### Backed by technologies
1. Agents - are llms interact with Real-Word by usage of tools
2. RLM (Recursive Language Models) - modl offload answers out of it context window to bypass Lost-in-the-middle scenario where LLM faithully remembers start and end of conversation alhought lost the clue about bigger part of informations were in the middle
3. MEMRL - (keep old tasks to success ratio) to pick the best recipie for given task base on hisotical experiences of user. Avoids "Catastrophic-Forgetting" scenario
4. Skills - give it skills. While making answer to your questions model learns new stuff developing skills in folder "skills" -> you can overwrite then these skills, delete or make new
5. CASCADE - if model hasn't got required tool - it makes it with use of code and vm to test whether it works (debugging buggggy code - pretty usual for even **Frontier LRMs**)
6. STaR - for users like to fine tune their models for their tasks
7. Scratchpad - the result of LLM "cognitive" are wroten down on scratchpad cards (aboce the user question)
8. Extensions - users can share skills, tools for other users to make the agents/llms processing tasks even better (this will be done as shop). 
    - Extensible UI - users can in shop publish the extension is changing/extensing the agents response with visual aspect
    - Extensible Plugins - users can make the plugins for ai
    - Tools - users can make prebuild tools
    - MCP - users can share their mcps

9. Locally hosted models - use locally hosted models with ollama
10. Providing resources - user can provide resources to be computing e.g: other files from desktop and/or mention files from local file base but as default these are mentioned prior
11. Selecting other documents in text content - user can in question select next documents with use of `@` command - this will include in prompt the file and its content
